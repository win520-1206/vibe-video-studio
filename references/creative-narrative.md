# 知识、动画与情绪共同叙事

## 从疑问推导过程

开始时了解主题、受众和希望观众带走的思考。知识、哲理不是两种互斥模式：真实机制回答为什么，情绪与感悟连接人的经验。允许从异常、任务或反事实切入；故事顺序依题材安排，不固定四幕、时长或内容比例。

先列开场问题，再写观众原先可能如何理解、哪个可见过程改变这种理解，以及结尾如何回应。把一段话拆成对象、条件、动作与结果。文案初稿可删冗、换序；确认后不漏掉限定、否定和数值。不能仅靠换字幕推进解释，也不以减少文字为由擅删确认稿。

情绪应有过程来源：等待某个结果产生期待，对照暴露差异形成惊讶，纠偏过程使担心转为可理解的调整。音乐加强这些节点；不要把科学结论包装成命运或人际关系的证明。必要时在相关镜头标示“示意”“模型”或“类比”，完整依据进入资料。

## 创作表接口

`npm run plan:shots`读取原始project-contract.json生成creative-plan.json和docs/creative-plan.md，不要求renderer已实现。JSON为创作母本，Markdown为生成时的阅读快照，两者存在其一就停止生成，避免覆盖。

schemaVersion=1。project填写openingQuestion、coreMechanism、insight、emotionalConnection、endingResponse。shots逐镜填写episodeId、sceneId、captionIds、eventIds、action、viewerBefore、viewerAfter、emotionalBeat、transition。没有profile，也没有start/end、独立字幕或复制的音乐时刻。镜头时段、完整原稿与事件时间都引用工程配置。

`npm run check:creative`检查全部场景恰好覆盖一次、原稿清单一致、文案归属、事件存在且在镜头半开区间内、动作和认识变化等是否填写；缺创作表明确报错并提示生成。参考文字/动作引用的事件不能遗漏，镜头内其他有效事件可以补充。读取script-manifest.json作为独立确认稿，不从创作表推断它。

结果写入qa/creative-report.json，更新后的阅读版写qa/creative-plan.md，不覆盖作者的docs快照。科学准确、类比边界、视觉理解、情绪自然和音乐效果始终记录为not_reviewed，不能因字段完整自动通过审美验收。其他工程命令继续兼容没有创作表的项目；交付时存在的创作表一同打包。

## 示例一：相遇之后

开场“相遇，会让彼此消失吗？”先呈现两个相反位移的脉冲。观众担心消失，镜头让它们在同一介质中接近；文字引入线性介质与位移相加的条件。相遇瞬间，实线合位移变平，虚线保留分量，音乐候选重音与“相消”同事件。随后分量穿过彼此、重新分离，原先对消失的判断得到修正。

结束“眼前的平静，未必是终点”是作者对过程的感受。它不证明关系如何发展。脉冲是理想线性、无色散模型，介质标记点不是随波迁移的物质；瞬时位移为零不代表能量为零。

依据：[OpenStax波的干涉](https://openstax.org/books/university-physics-volume-1/pages/16-5-interference-of-waves)。示范有独立解析模型和求和/传播测试。

## 示例二：修正的方向

开场“偏离目标，就意味着失败吗？”让滑块实际偏离目标。反馈开启后，测量、比较、修正形成闭环，箭头长度编码修正量；偏差曲线与滑块共享模型。对象逐渐靠近目标，扰动再次推离它，反馈继续响应。期待与担心来自对象状态，不依靠增加背景粒子。

结束“调整方向，也是一种前进”是作者感悟。演示仅使用理想积分对象dx/dt=u与负比例控制u=-k(x-r)，无延迟或饱和，误差按指数衰减，有限时刻不精确归零；不能推广为所有反馈都稳定或越强越好。

依据：[密歇根大学反馈控制入门](https://eecs.umich.edu/courses/eecs373.w05/lecture/control.html)、[CTMS控制教程](https://ctms.engin.umich.edu/CTMS/index.php?example=Introduction&section=ControlPID)。示范以数值积分独立核对解析结果。

## 实际片段复核

遮掉正文后能否认出变化？变化是否回答问题？担心或释然是否由过程产生？结论是否超出证据？音乐揭示是否对应理解发生变化？两个题材是否确有不同主体和运动方式？这些问题结合连续观看和实际审听回答；无法审听时标明未完成，不把信号峰值当成听懂了音乐。
